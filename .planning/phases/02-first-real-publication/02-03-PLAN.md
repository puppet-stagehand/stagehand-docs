  <instructions>
    I requested the ACM certificate for `testpilots.puppetstagehand.com`. AWS will not issue it
    until it can see one DNS record proving control of that name:

    Name: {captured `resource_record_name` from Task 1}
    Type: CNAME
    Value: {captured `resource_record_value` from Task 1}

    Add exactly this one record in Cloudflare's existing DNS management for `puppetstagehand.com`
    (the domain's current, live, authoritative DNS host).

    This is deliberately NOT an NS delegation change and does not touch `puppetstagehand.com`'s apex
    or `www` records — Cloudflare stays 100% authoritative for the whole domain throughout, and the
    live GitHub Pages site those records currently serve is untouched. D-01 (02-CONTEXT.md, LOCKED)
    forbids a full-domain NS cutover; D-02 forbids touching the live NS delegation itself; neither
    forbids adding one new, previously-nonexistent validation record for a name that has never
    resolved to anything. D-03 defers the actual domain cutover (the live registrar/NS pointing at
    Route 53) — this record does not perform that cutover: `testpilots.puppetstagehand.com` will
    still not resolve for a random visitor afterward, because Cloudflare has no A/AAAA record for
    that name and still is not delegating it. Only the ACM validator (which follows the standard
    public DNS chain, currently rooted at Cloudflare) needs to see this one record.

    If you disagree with this approach, do not add the record — instead reply describing your
    preferred alternative and I will stop here rather than proceed with the testpilots apply.
  </instructions>
  <verification>Once you confirm the record is added, I will poll `dig +short CNAME "{resource_record_name}"` (a read-only public DNS query) with bounded retries until it resolves to the expected value, or report back if it does not appear within a reasonable window.</verification>
