<objective>
Rework the build-isolation guarantee from "the production register is empty" to "the production register
contains no fixture-derived record," via RED-GREEN-REFACTOR, so a real reviewed compatibility record can
ship without weakening evidence validation and without breaking `npm run verify`.

Purpose: `scripts/check-e2e-build-isolation.ts` currently throws unless `dist/data/compatibility.json` has
exactly zero records — a hard build break the instant COMP-01 review produces the first real record. This
is the single mechanism COMP-03 requires, and 04-RESEARCH.md's Pitfall 2 explicitly warns that rewriting a
checker's logic without a negative-path test is how a security-adjacent gate ships silently broken (an
`if` that never evaluates false in any test).
Output: a content-cross-reference leak detector in `scripts/check-e2e-build-isolation.ts`, an exported
`identityOf` in `src/lib/data/compatibility.ts`, and a rewritten `tests/unit/e2e-build-isolation.test.ts`
proving both the pass path (clean production + real e2e/scale counts) and the reject path (a leaked
record, caught by id and by identity tuple).
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-04-03 | Tampering | Isolation checker's id/identity leak detection | medium | accept | A contributor could hand-copy a fixture record's content into `src/data/compatibility.yaml` while also changing both its `id` and one identity field, evading both checks (RESEARCH.md Assumption A1).
