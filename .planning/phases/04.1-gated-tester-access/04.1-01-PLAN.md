<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet -> CloudFront viewer-request function | The gate's entire enforcement point; runs before any origin (S3) is reached. |
| Compiled function source (Terraform `code` argument) -> committed repository | `gated-paths.json` and the function template are both committed; neither may ever contain the credential value itself. |
| CloudFront Function runtime -> CloudFront KeyValueStore | A new, previously-unused (in this repo) trust relationship — the function's only source of the real credential at runtime. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-01 | Information Disclosure | `redirect.js`, `gated-paths.json`, `kvs.tf` | high | mitigate | No file this task creates or edits contains the credential value — only a KVS *key name* (`gate_expected_header`) and the gated-path list. The value is written out-of-band in Plan 04.1-02. |
| T-04.1-02 | Denial of Service / Improper Error Handling | `cf.kvs().get(...)` call inside the async gate branch | high | mitigate | Wrapped in `try`/`catch` returning `unauthorized()` on any failure — a KVS outage, missing key, or unexpected runtime error fails closed (401), never falls through to serving gated content. |
