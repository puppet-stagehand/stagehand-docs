<decisions>
## Implementation Decisions

### Tester's Guide port (decided while scoping Phase 04.2's downloads work)
- **D-01:** The Tester's Guide ports from `puppet-console`'s `docs/TESTER-GUIDE.md` into a
  dedicated area of `stagehand-docs`, gated by the same AUTH-01 mechanism as any other testing
  guide.
- **D-02:** It must render only on `testpilots` and `beta` — **not** `stable`. Per PROJECT.md's
  immutable-promotion constraint ("one full 40-character SHA" promoted unchanged testpilots →
  beta → stable), this cannot be done with a different build per environment. Resolution:
  **client-side hostname detection** — the identical static bundle ships to all three
  environments; a runtime script reads `window.location.hostname` and renders either the guide
  content or an honest "not available on this site" state. This is the same runtime-detection
  approach Phase 04.2 uses for its per-channel downloads page (see `04.2-CONTEXT.md` D-05) — reuse
  whatever hostname-detection utility that phase produces rather than writing a second one.
- **D-03:** This does NOT change AUTH-05's single-source-of-truth requirement — the Tester's Guide
  path still needs to be declared in the one place both the CloudFront function and verification
  tooling read as a gated path; testpilots/beta-only *visibility* is a separate, additional runtime
  concern layered on top of the *access* gate, not a replacement for it.

### Claude's Discretion
- Where exactly the hostname-detection utility lives (shared module vs duplicated small script) is
  left to whichever phase's plan lands first — 04.1 or 04.2 — with the other phase reusing it.

### Existing temporary whole-site Basic Auth (found during research, 2026-08-27)
- **D-04:** Commit `44b56c9` (this session, before this discussion) added a **temporary whole-site**
  HTTP Basic Auth lockdown to all three live environments (`enable_basic_auth` in
  `infra/environments/{testpilots,beta,stable}/main.tf`), reusing the same `redirect.js` CloudFront
  Function this phase must extend for AUTH-01's gate logic — CloudFront allows only one function per
  event type per cache behavior, so both mechanisms share that file.
- **D-05:** Decision: **keep both, layered** — do not remove the whole-site Basic Auth as part of
  this phase. The new AUTH-01..06 KVS-based gate is added as an additional, separate mechanism
  scoped to testing guides (and now the Tester's Guide), inside the same function file. Whether the
  whole-site lockdown ever comes off is a decision for a later phase, not this one.
- **D-06:** Because AUTH-03 requires that rotating the *new* shared password never requires
  republishing the function, and the *existing* whole-site Basic Auth is baked in via Terraform
  string-substitution (which does require a republish to rotate), the plan must keep these two
  credential lifecycles clearly separate in the runbook — do not conflate "rotate the tester
  password" with "rotate the whole-site Basic Auth credential," and do not let AUTH-03's guarantee
  accidentally imply the whole-site lockdown also gained KVS-based rotation (it has not).

### Tester's Guide porting depth (found during research, 2026-08-27)
- **D-07:** `puppet-console/docs/TESTER-GUIDE.md` is 1375 lines of internal engineering QA
  changelog with zero images/relative links (mechanically portable) but full of
  `puppet-console`-internal references not meaningful to an external tester. Decision: **trim to
  tester-relevant content** — port only the sections a tester actually needs (setup, how to test,
  how to report issues), dropping internal engineering changelog entries. The planner/executor
  should read the full source file and use judgment on what's tester-relevant; this is a content
  edit, not a mechanical copy.

</decisions>
