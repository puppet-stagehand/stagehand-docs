<objective>
Gap closure for 04.1-REVIEW.md's CR-01 (blocker), routed into 04.1-UAT.md test 3: the Tester's
Guide visibility toggle (`TesterGuideVisibility.astro` + `DocsLayout.astro`) currently fails
**open** — the guide body is server-rendered visible and the "not available on this site" fallback
hidden by default, and only a successfully-executing client script narrows visibility down for a
disallowed channel. Any visitor whose browser never runs that script, for any reason, sees the
guide on `stable`, which should never happen. This plan inverts the default so the mechanism fails
**closed**: hidden-guide/visible-fallback by default, revealed only when the toggle script proves
an allowed channel (`testpilots`/`beta`).

This is independent of, and does not touch, the already-accepted D7/AUTH-06 pre-launch gap (the
temporary whole-site `enable_basic_auth` lockdown blocking the toggle script's own asset request —
tracked in `.planning/WINDOWS.md` id 2, out of scope here per the orchestrator's instructions). That
gap explains one specific cause of the script not running; this plan fixes the underlying fail-open
*design* so the mechanism is safe regardless of cause.

Purpose: AUTH-06 (Tester's Guide renders only on testpilots/beta, honest fallback on stable — this
plan makes that guarantee hold even when the deciding script doesn't run), GATE-06 (the gating
mechanism's correctness is proven by a real, automated test, not asserted).
Output: `DocsLayout.astro` and `TesterGuideVisibility.astro` inverted to a safe default; a new
Playwright e2e spec (`tests/e2e/tester-guide-visibility.spec.ts`) proving the no-JS/script-not-run
fail-closed behavior alongside the existing working-script behavior for both allowed and
disallowed channels.
</objective>
