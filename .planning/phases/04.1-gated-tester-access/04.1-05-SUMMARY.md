## Accomplishments
- Closed 04.1-REVIEW.md's CR-01 blocker: the Tester's Guide body no longer server-renders visible by default. `DocsLayout.astro`'s `.docs-content` div now carries `hidden={entry.data.visibleOn ? true : undefined}`, and the `data-tester-guide-unavailable` fallback paragraph renders visible (no `hidden` attribute) by default — matching the exact same `visibleOn`-scoped conditional both elements already used, so no other `/docs/` page is affected.

## Decisions Made
- **Hostname spoofing technique substitution (Rule 3 — blocking issue):** The plan's suggested `page.addInitScript` technique for overriding `window.location.hostname` (both the direct-property form and the whole-`location`-object fallback it specifies) throws `TypeError: Cannot redefine property` against the Chromium build in this environment, because `hostname` is a non-configurable *own* property on the `Location` instance (verified interactively — even redefining `Location.prototype.hostname` had no effect, confirming the instance property shadows the prototype). Replaced with a dedicated `chromium.launch({ args: ['--host-resolver-rules=MAP <hostname> 127.0.0.1'] })` instance per test (Tests B/C), which produces a genuine, unmocked `window.location.hostname` by resolving the real hostname to the already-running `production` project webServer on port 4321. This is a technique substitution to satisfy the plan's stated behavior contract (Tests B/C must exercise the real hostname-based channel resolution), not a scope change — no plan file outside `tests/e2e/tester-guide-visibility.spec.ts` was touched for this.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Playwright hostname override technique from the plan didn't work on this Chromium build**
- **Found during:** Task 1 (writing Test B/C's hostname override)
- **Issue:** Both `Object.defineProperty(window.location, 'hostname', ...)` and the whole-`window.location`-object fallback the plan specified throw `Cannot redefine property` — `Location.hostname` is a non-configurable own instance property on this Chromium version, so neither `page.addInitScript` form can reassign it.
- **Fix:** Verified the failure interactively with a throwaway debug script (`chromium.launch()` + `page.addInitScript` + `page.on('pageerror', ...)`), confirmed a `--host-resolver-rules` DNS-mapping approach works reliably, then rewrote Tests B/C to launch a dedicated `chromium` instance per test with that flag instead of using the shared `page` fixture's `addInitScript`.
- **Files modified:** tests/e2e/tester-guide-visibility.spec.ts
- **Verification:** Test A/B/C all pass after Task 2's fix; Test A alone fails (for the correct reason) after Task 1, matching the plan's stated RED-state acceptance criteria.
- **Committed in:** c8679d3 (Task 1 commit)
