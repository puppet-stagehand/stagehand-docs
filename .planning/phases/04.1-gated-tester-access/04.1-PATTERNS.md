## Pattern Assignments

### `infra/modules/static-site/functions/redirect.js` (middleware, request-response)

**Analog:** itself — extend in place, do not replace.

**Existing full-file structure** (already read in full, `infra/modules/static-site/functions/redirect.js:1-68`):
```javascript
function unauthorized() {
  return {
    statusCode: 401,
    statusDescription: 'Unauthorized',
    headers: {
      'www-authenticate': { value: 'Basic realm="Restricted", charset="UTF-8"' },
      'cache-control': { value: 'no-store' },
    },
  };
}

// eslint-disable-next-line @typescript-eslint/no-unused-vars -- CloudFront invokes this global entry point.
function handler(event) {
  var request = event.request;
  var uri = request.uri;
  var query = encodeQueryString(request.querystring);
  var apexRedirectEnabled = __ENABLE_APEX_REDIRECT__;
  var basicAuthEnabled = __ENABLE_BASIC_AUTH__;

  if (basicAuthEnabled) {
    var authHeader = request.headers.authorization;
    if (!authHeader || authHeader.value !== '__BASIC_AUTH_EXPECTED_HEADER__') {
      return unauthorized();
    }
  }

  if (apexRedirectEnabled && request.headers.host.value.toLowerCase() === 'puppet-stagehand.com') {
    return redirect('https://www.puppet-stagehand.com' + uri + query);
  }
  // ... clean-path logic unchanged below
}
```

**Pattern to copy:** the existing `basicAuthEnabled` guard clause (string-compare against a Terraform-templated placeholder, `unauthorized()` reused verbatim) is the direct template for the new KVS-backed gate guard. Insert the new gated-path check as an **earlier** guard clause (before the existing `basicAuthEnabled` block, since both may be active simultaneously per D-05), reusing `unauthorized()` unchanged. The new guard needs `async function handler(event)` (a signature change — see RESEARCH.md Pitfall 7 for the `vm.runInContext` test-harness implication) and a placeholder-substitution constant (`__GATED_PATH_PREFIXES__`) following the exact same `String(...)`/`.replace(...)` idiom already used for `__ENABLE_APEX_REDIRECT__` / `__ENABLE_BASIC_AUTH__` / `__BASIC_AUTH_EXPECTED_HEADER__`.

**Error handling pattern:** none needed beyond what exists — `unauthorized()` is the single failure-path helper; reuse it, do not create a second one. Malformed `Authorization` headers must not throw (see Pitfall in RESEARCH.md V5) — follow the existing defensive style of `!authHeader || authHeader.value !== ...` (short-circuit before touching `.value`).

### `infra/modules/static-site/cloudfront.tf` (config, CRUD) + `kvs.tf` (NEW)

**Analog:** itself, `aws_cloudfront_function.redirect` block (lines 123-145), and the cache-policy resource blocks (lines 9-32) as a structural template for a new standalone resource.

**Existing function-templating pattern** (`cloudfront.tf:123-145`):
```hcl
resource "aws_cloudfront_function" "redirect" {
  count = var.enable_redirect_function ? 1 : 0

  name    = "stagehand-${var.environment}-site-paths"
  comment = "Canonical host redirect and clean static-site paths"
  runtime = "cloudfront-js-2.0"
  publish = true
  code = replace(
    replace(
      replace(
        file("${path.module}/functions/redirect.js"),
        "__ENABLE_APEX_REDIRECT__",
        tostring(local.enable_apex_redirect),
      ),
      "__ENABLE_BASIC_AUTH__",
      tostring(var.enable_basic_auth),
    ),
    "__BASIC_AUTH_EXPECTED_HEADER__",
    local.basic_auth_expected_header,
  )

  tags = local.required_tags
}
```
**Pattern to copy:** add one more nested `replace(...)` call for `__GATED_PATH_PREFIXES__`, sourced from `jsondecode(file("${path.module}/gated-paths.json"))` per RESEARCH.md's recommendation — follow the exact nested-`replace` chain style already established (do not refactor to a different templating mechanism, e.g. `templatefile()`, without reason — the existing three-placeholder chain is the established convention here).

**Naming/tagging convention to copy** (applies to the new KVS resource in `kvs.tf`): `name = "stagehand-${var.environment}-<thing>"`, `tags = local.required_tags` — every resource in this file follows this. RESEARCH.md's own verified example already matches this convention:
```hcl
resource "aws_cloudfront_key_value_store" "tester_gate" {
  name    = "stagehand-${var.environment}-tester-gate"
  comment = "Shared-password gate for testing guides (AUTH-01/02/03)"
  tags    = local.required_tags
}
```

**Association pattern:** the existing `dynamic "function_association"` blocks (lines 176-184, 196-204, 216-224) appear identically in all three cache behaviors — `key_value_store_associations` is a plain list attribute on `aws_cloudfront_function.redirect`, not a per-behavior association, so it only needs to be added once to the `aws_cloudfront_function` resource itself, not replicated into each `dynamic` block.

**Local-value convention to copy** (`locals.tf:1-20`): comment-then-value style, e.g. the `basic_auth_expected_header` local's preceding comment explaining *why* the value is precomputed. Any new derived local (e.g. compiling `gated-paths.json` into a Terraform list) should follow this same comment-first convention.

### `infra/modules/static-site/tests/gate.test.mjs` (test, request-response)

**Analog:** `infra/modules/static-site/tests/redirect.test.mjs` (full file already read, 120 lines).

**Harness pattern to copy** (`redirect.test.mjs:1-16`):
```javascript
import assert from 'node:assert/strict';
import { readFileSync } from 'node:fs';
import test from 'node:test';
import vm from 'node:vm';

const template = readFileSync(new URL('../functions/redirect.js', import.meta.url), 'utf8');

function loadFunction(apexRedirectEnabled, basicAuthEnabled = false) {
  const context = vm.createContext({});
  const source = template
    .replace('__ENABLE_APEX_REDIRECT__', String(apexRedirectEnabled))
    .replace('__ENABLE_BASIC_AUTH__', String(basicAuthEnabled))
    .replace('__BASIC_AUTH_EXPECTED_HEADER__', 'Basic dGVzdDp0ZXN0');
  vm.runInContext(source, context);
  return context;
}
```
**Required extension (per RESEARCH.md Pitfall 7):** the new gate branch makes `handler` `async`, and needs a `cf` global injected into `vm.createContext({...})` since `import cf from 'cloudfront'` cannot run under `vm.runInContext`. Strip the import line before evaluating, and pass a mock:
```javascript
const context = vm.createContext({
  cf: { kvs: () => ({ get: async (key) => mockKvs[key] }) },
});
```
All test bodies that exercise the async gate branch must `await context.handler(event)` — existing synchronous calls (e.g. `context.handler(request(...))` at lines 31, 46, 53...) remain valid for non-gate-branch tests only if `handler` stays backward-callable; if `handler` becomes fully `async`, **every** existing call site in `redirect.test.mjs` needs `await` added too (breaking change to the existing file, not just an addition).

**Request-fixture helper to copy verbatim** (`redirect.test.mjs:20-28`):
```javascript
function request(uri, host, querystring = {}, headers = {}) {
  return {
    request: {
      uri,
      headers: { host: { value: host }, ...headers },
      querystring,
    },
  };
}
```

**Assertion style to copy** (`redirect.test.mjs:90-105`, the existing basic-auth-401 tests are the direct template for the new gate's 401/pass-through tests):
```javascript
test('basic auth enabled rejects a request with the wrong credential', () => {
  const authContext = loadFunction(false, true);
  const result = authContext.handler(
    request('/tiers/', 'beta.puppet-stagehand.com', {}, { authorization: { value: 'Basic wrong' } }),
  );
  assert.equal(result.statusCode, 401);
});
```

### `src/lib/site-channel.ts` (utility, transform) — NEW, no strong in-repo analog

No existing `src/lib/*.ts` pure-function module was read this session to extract an exact style precedent (only `navigation.ts` was cited in RESEARCH.md's file list, not independently re-read here). Use RESEARCH.md's verified specification directly as the pattern source (hostnames independently verified against `infra/environments/*/main.tf`):
```typescript
export type SiteChannel = 'testpilots' | 'beta' | 'stable' | 'unknown';

export function resolveSiteChannel(hostname: string): SiteChannel {
  if (hostname === 'testpilots.puppet-stagehand.com') return 'testpilots';
  if (hostname === 'beta.puppet-stagehand.com') return 'beta';
  if (hostname === 'www.puppet-stagehand.com' || hostname === 'puppet-stagehand.com') return 'stable';
  return 'unknown';
}
```
**Cross-phase note:** per CONTEXT.md's Claude's-Discretion note, this file is shared with Phase 04.2's downloads-page channel resolution — whichever phase's plan lands first creates it; the other imports it unchanged. Do not duplicate this logic into a second file.
