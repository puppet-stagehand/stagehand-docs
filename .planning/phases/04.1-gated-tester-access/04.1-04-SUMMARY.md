## Decision Needed

**What was found:** A real tester, holding only the shared tester password (no other
credential), cannot get a fully-functional `/docs/testers-guide/` page on any of the three real
environments right now. The HTML itself loads (the gated route matches, 401→200 as designed),
but every static asset the page references — its CSS bundle, the client-side
`TesterGuideVisibility` toggle script, and the Puppet logo — sits under paths
`gated-paths.json` never declared, so they fall to the *separate*, pre-existing
`enable_basic_auth` whole-site lockdown (`enable_basic_auth = true` on all three environments
today). Both auth mechanisms challenge with the identical realm string
(`WWW-Authenticate: Basic realm="Restricted"`), so a browser's single cached Authorization
header can satisfy only one of them. Concretely: the toggle script never loads for a tester, so
it never runs, so AUTH-06's "stable shows the fallback" guarantee does not hold live — stable
renders the full guide body instead, identically to beta and testpilots.

**Why this isn't auto-fixed:** `redirect.js`'s own comment documents this separation as
deliberate (D-05: "every other path keeps the pre-existing `enable_basic_auth` behavior,
completely unaffected"; D-06: the two credentials must never be evaluated against the same
header). Changing which paths the tester credential unlocks, or exempting static assets from
the whole-site lockdown, changes that documented security boundary — squarely a Rule 4
"changing auth approach" architectural decision, not mechanical integration drift.

**Options, roughly in order of invasiveness:**

1. **Accept as an expected pre-launch-only limitation.** Confirmed, not merely plausible:
   commit `44b56c9` ("add temporary HTTP Basic Auth lockdown to all environments", made the
   evening before this session) states its purpose explicitly — "so the newly-live
   puppet-stagehand.com sites stay gated behind credentials while the rebrand and content work
   is still in progress." A same-day follow-up, `cd0e397`, had to patch
   `check-live-deployment.ts` because this lockdown broke deploy verification too ("The
   temporary HTTP Basic Auth lockdown ... has broken every deploy since"). This whole-site
   lockdown is explicitly temporary, out-of-phase infrastructure — not part of 04.1's own
   design — and is the most likely candidate for removal at Phase 05's (LAUN) public-launch
   cutover. Once removed, every non-gated path (including these assets) becomes freely
   fetchable with no credential, and the toggle script will load and run correctly with zero
   code change here. If this reading is correct, testers during the pre-launch window need
   *both* credentials distributed to them out-of-band (process fix, not a code fix), and this
   plan can close with check 6 documented as "verified against the post-launch config; not
   currently observable pre-launch" rather than a hard failure.
2. **Broaden `gated-paths.json` to cover the specific static-asset paths the gated page
   needs** (e.g. add `/assets/` and `/brand/` as additional gated prefixes, or maintain an
   explicit allow-list of the guide's compiled asset filenames). Smallest code change, but
   widens what the shared tester password unlocks beyond the one documented route, and
   `/assets/` is shared by *every* page on the site, not just the gated one — needs sign-off
   on whether that scope expansion is acceptable.
3. **Exempt static assets (`/assets/`, `/brand/`) from `enable_basic_auth` site-wide**, so
   they always load without any credential regardless of environment or gate status — a common
   pattern for basic-auth-protected sites (gate the documents, never the bundles). Cleanest
   long-term architecture, but is a security-boundary change to the *pre-existing*, out-of-phase
   whole-site lockdown, not something 04.1 owns.

**This plan does not select an option.** A follow-up decision (and, if needed, a
`04.1-04-RESOLUTION.md` or a small follow-up plan) should record the choice and, if code
changes result, complete check 6 for real before Phase 04.1 is marked complete in STATE.md.
