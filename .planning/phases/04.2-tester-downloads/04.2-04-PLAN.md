<objective>
Close the one unresolved gap from 04.2-VERIFICATION.md: CR-01 (04.2-REVIEW.md), where `loadDownloads()`
in `src/lib/data/downloads.ts` documents a "never throw" contract but does not honor it for the
per-channel processing loop. A `200 OK` response whose JSON body isn't an array, or whose matched
release has a `null`/missing `assets` field, currently throws an uncaught `TypeError` out of
`loadDownloads()` — which is awaited directly inside two Astro static-route components, so the throw
fails the entire `astro build`, not just the Downloads page. This is a materially worse outcome than
the honest-unavailable state Roadmap SC 5 and DOWN-04 require.

Purpose: close CR-01 per its own suggested fix — validate the releases-list body shape before use,
and wrap the whole per-channel loop body in try/catch so any per-release malformation degrades only
that one channel to `null` instead of crashing the build.
Output: `loadDownloads()` never throws regardless of upstream JSON shape, proven by two new unit
tests reproducing CR-01's exact failure mode, with zero regression to the 16 already-passing tests
in `tests/unit/downloads-data.test.ts` and `tests/unit/downloads-channel.test.ts`.
</objective>
