<objective>
Build `/downloads/`: a channel-matched puppet-installer download page sourced entirely from the
public `puppet-stagehand/stagehand-release` repository's GitHub Releases API (D-01/D-02 — that repo
is a corrected mirror target; `puppetlabs-seteam/puppet-installer` itself is private and never
touched by this phase's code, per D-04), resolved at runtime via client-side hostname detection
(D-05 — the same immutably-promoted build ships to all three sites, so this cannot be a
per-environment build) and explicitly ungated (D-06/DOWN-03). As of 2026-08-28 the mirror repo does
not exist and has zero releases published anywhere (D-07) — this plan's honest-unavailable path is
not a hypothetical edge case, it is the page's real, current production behavior, and the code must
prove it degrades gracefully rather than crashing the build when the upstream API 404s.

Purpose: DOWN-01 (channel-matched download, version stated), DOWN-02 (public-repo-only data
source), DOWN-03 (ungated), DOWN-04 (checksum + publication date, honest unavailable state), GATE-07
(fixture-proven channel resolution with no silent fallback).
Output: `src/lib/data/downloads.ts` (an injectable-fetch, build-time loader), the
`/data/downloads.json` API route, the `/downloads/` page, and the client-side channel-reveal
component — all proven against fixtures per GATE-07; live verification against the real mirror repo
is tracked separately once the cross-repo prerequisite lands (see Plan 04.2-03).

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Build tier (Node, `astro build`) -> `api.github.com`/release-asset host | An untrusted external API response (release body text, `SHA256SUMS` asset content) crosses into this repo's build process. |
| `puppet-stagehand/stagehand-release`'s write access -> this build's parsed output | Anyone with write access to the public mirror repo can shape the `Channel:`/`SHA256SUMS` text this build parses (D-02's mirror-step target). |
| Client-side hostname read -> which channel's data is revealed | A purely cosmetic display decision (D-05), not an access-control boundary — DOWN-02's real protection is that only the public repo's data is ever fetched, never a credentialed one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.2-01 | Tampering | `src/lib/data/downloads.ts`'s release-body/SHA256SUMS parsing | medium | mitigate | Defensive parsing only: regex `.exec()`/`.find()` returning `undefined` on no match, try/catch around both fetches, any parse/fetch failure degrades exactly the affected channel to `null` — never throws out of `loadDownloads` and never crashes the site build (Task 1/2's behavior contract, matching D-07/Pitfall 8). |
| T-04.2-02 | Information Disclosure | `src/lib/data/downloads.ts`'s fetch target | high | mitigate | The only network target this phase's code ever calls is the already-public `puppet-stagehand/stagehand-release` repo's public, unauthenticated API (D-01/D-02) — no token, credential, or reference to the private `puppetlabs-seteam/puppet-installer` repo is introduced anywhere in this plan's files; Task 3's closing sweep greps for the private repo's name to confirm it never appears. |
| T-04.2-03 | Tampering / Repudiation | The rendered checksum/publication-date pair on `/downloads/` | medium | mitigate | Publication date is always shown alongside the checksum (DOWN-04); a channel with no parseable `SHA256SUMS` never shows a synthesized or guessed checksum — it falls back to the honest-unavailable state for that channel instead (Task 2). |
