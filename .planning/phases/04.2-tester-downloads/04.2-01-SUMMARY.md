**Build-time GitHub Releases loader and `/downloads/` page that fail-closes to an honest "no release yet" state today (D-07) and is unit-proven, via injectable-fetch fixtures, to resolve real per-channel release data with no cross-channel leak once `puppet-stagehand/stagehand-release` exists (GATE-07).**

## Accomplishments

- `src/lib/data/downloads.ts`: injectable-fetch `loadDownloads()` that fetches the public
  `puppet-stagehand/stagehand-release` Releases API, matches each channel's latest release via its
  `` Channel: `<name>` `` body line, fetches and parses that release's `SHA256SUMS` asset, and
  degrades exactly the affected channel to `null` on any failure — never throwing out of the Astro
  build, matching today's real zero-releases state (D-07/Pitfall 8).
- `releaseChannelFor()`, the one dedicated, unit-tested place `resolveSiteChannel()`'s
  `'testpilots'` output is mapped to the release data's hyphenated `'test-pilots'` key
  (Pitfall 3) — never compared directly anywhere else in the codebase.
- `/downloads/` page: three `[data-channel]` sections, each starting `hidden` (a deliberately
  different default than `TesterGuideVisibility.astro`'s fail-open pattern, since showing the
  wrong channel's binary here is a correctness bug, not an access-control nicety), a `noscript`
  manual-fallback link, and `DownloadsChannelVisibility.astro`'s client-side reveal.
- DOWN-03/D-06 proven, not assumed: a dedicated test reads `gated-paths.json` and asserts it never
  contains `/downloads` or any prefix of it.
- Closed-enumeration lists (`check-built-routes.ts`'s `requiredOutputs`,
  `deploy-site.sh`'s CloudFront invalidation `--paths`, `navigation.ts`'s `primaryNavigation`) all
  updated together, per this project's route-coupling constraint.

## Decisions Made

- Extended `ChannelRelease` with a `downloadUrls` field beyond the plan's originally sketched
  shape, because DOWN-04's "state only what's known" requirement needs the actual GitHub asset URL
  per binary, independent of whether that binary also appears in `SHA256SUMS`.
- Treated an all-blank/unparseable `SHA256SUMS` body (parses to an empty checksums map) as a
  fetch-equivalent failure, degrading that channel to `null` rather than showing a release with
  zero checksums.
- Reused `CompatibilityEmptyState.astro`'s `.compat-empty`/`.compat-card` CSS classes instead of
  adding a new SCSS partial, since no new stylesheet file was in this plan's declared file scope.
