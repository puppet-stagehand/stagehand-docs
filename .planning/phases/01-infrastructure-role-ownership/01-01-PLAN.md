<assumption_delta_decision>
**Detected:** `pluralization` — the GitHub Environment model moves from a three-value enumeration
(`testpilots`, `beta`, `stable`) to six Environments, one plan and one apply per Stagehand
environment, and CI role identity follows it.

**Primary noun (now):** the **(Stagehand environment, operation) pair**, where `operation` is `plan`
or `apply`. The bare `environment` is no longer the identity key for anything that binds to a GitHub
Environment or an AWS role; it survives as the identity key for exactly one thing — the OpenTofu
deployment target and its `environment` resource tag value, which ADR-0002 rule 2 fixes at three.

**Decision: `promote`.** The `(environment, operation)` pair becomes the primary key for role
identity, trust subject, permission policy, and published output. The three-value `environment` enum
is demoted from "the identity" to "one component of the identity", retained in its own narrower role
as the tag-value namespace.

*Rationale:* ADR-0002 rule 3 already generalized the Environment model; a role scheme keyed on the
singular `environment` cannot represent two roles per environment without either sharing a role
(forbidden by ADR-0003 rule 2) or smuggling the operation into a name suffix that nothing validates.
Promoting the pair makes the six-role invariant structural rather than conventional.

*Not `add-alongside`:* keeping a singular-environment role concept beside the pair would reintroduce
exactly the collapse ADR-0002 exists to prevent, where a single `testpilots` identity has nowhere to
put both a read-only and a mutating authority.

**Suggested invariant test (optional, not required by this plan):** *no role ARN or permission
policy produced for one Stagehand environment is valid in another, for every supported environment.*
The `forbids_escalation_actions_in_every_role_policy` run in plan 01-02 already carries the
cross-environment half of this; a future phase reintroducing a shared or singular role would go red
there.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → AWS STS | An OIDC token minted by GitHub crosses into AWS and is exchanged for credentials. The trust policy is the only thing deciding which token is accepted. |
| Pull-request code → plan Environment | Untrusted contributor code runs in the same workflow that attaches a plan Environment. The permission policy is the last line if the same-repository guard and the branch rule both fail. |
| Repository diff → AWS authority | A merged change to `infra/bootstrap/` proposes new authority. It has no effect until an administrator applies it locally. |
